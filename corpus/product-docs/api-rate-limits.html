API rate limits

Last updated 12 May 2026. Applies to API version 2026-03-01.

Every API key is subject to two limits: a per-minute limit and a per-day limit. Both are applied per workspace, not per key, so two keys in the same workspace share the same allowance.

Plan Requests per minute Requests per day Concurrent requests
Starter No API access
Growth 60 10,000 4
Scale 300 100,000 16
Enterprise 1,000 Custom (default 1,000,000) 64
Burst allowance: a key may exceed its per-minute limit by up to 2x for at most 60 seconds in any 10 minute period. Burst traffic still counts toward the daily limit.

What happens when you hit a limit

The API returns HTTP 429 Too Many Requests with a Retry-After header containing the number of seconds to wait. The response body has error.code = "rate_limited". Requests rejected with 429 do not count toward your daily limit.

Checking your usage

Every response includes X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset headers for the per-minute window.

Need more?

Enterprise customers can request a higher daily limit through their customer success manager. Per-minute limits are not adjustable.
