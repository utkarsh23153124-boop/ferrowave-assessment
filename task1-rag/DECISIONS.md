## Stack

| Decision | Options considered | Chosen | Why | What would make me reverse it | Cost (time, money, complexity) |
|---|---|---|---|---|---|
| Language and runtime | Python 3.12, TypeScript | Python 3.12 | Every loader library I needed (pypdf, python-docx, bs4) and every retrieval library is first-class in Python; it is also what I can change fastest live. | A team standardised on Node, or a need to ship a single binary. | None beyond what the rest of the tasks already use. |
| Framework | LangChain; plain Python with the `openai` client; LlamaIndex | LangChain (core, community, classic, openai, text-splitters) | I planned plain Python and was asked to use LangChain. What it earns its place for: `Document` with metadata, header-aware Markdown splitting, FAISS save/load with a metadata filter, `EnsembleRetriever` fusion, and `with_structured_output` returning both the parsed schema and token usage in one call. Everything that decides trust (loaders, precedence, visibility, plan gate, citation verification) is plain Python on top of it, on purpose. | If a live-session change gets blocked by an abstraction (e.g. needing scores out of `EnsembleRetriever`, which does not expose them; I re-derive them from rank). At that point I would inline the ~150 lines it replaces. | Two extra packages to install, lazy-import surprises, and one hour understanding the 1.x package split (`classic` vs `community`). |
| Chat model | gpt-4o-mini; gpt-4o; Claude Haiku 4.5; local llama3.1 via Ollama | gpt-4o-mini via `RAG_CHAT_MODEL` | The task is extractive: pick the right chunk, quote it, choose a status. It does not need frontier reasoning. Measured $0.00034 per question with 1.8k input tokens. Structured output support is solid. Local llama3.1 was tried for Task 3 and could not reliably return the citation schema. | If the hidden question set shows reasoning failures (multi-document reconciliation, subtle plan logic). Switching is an env var; cost would rise about 15x to roughly $0.005 per question. | Requires an OpenAI key and network; the BM25-only mode covers the no-network case for retrieval but not generation. |
| Embeddings | text-embedding-3-small; text-embedding-3-large; local nomic-embed via Ollama; none (BM25 only) | text-embedding-3-small, with BM25 as the second retriever | 1536 dims, $0.02 per million tokens; the whole corpus embeds for under $0.001. Hybrid with BM25 because the corpus is full of exact tokens (`response.created`, `Retry-After`, "99.9%") that dense retrieval alone blurs. | If the corpus grew multilingual, or if BM25 alone passed the eval (it nearly does: retrieval tests pass offline). | One network dependency at index time and one per query (about 200 ms). |
| Vector store | FAISS (local files); Chroma; numpy dot product; pgvector | FAISS via LangChain | No server, save/load to the `index/` folder, and a metadata filter callable so hidden chunks are never returned. Honestly oversized for 276 vectors. | If the index needed to be shared between processes or updated incrementally. | 30 MB wheel. |
| API server | FastAPI; Flask; plain `http.server` | FastAPI + uvicorn | Request validation for free, `/health` and `/reindex` trivial to add, already installed. | Nothing realistic at this size. | None. |

## Design decisions

| Decision | Options considered | Chosen | Why | What would make me reverse it | Cost |
|---|---|---|---|---|---|
| What "customer facing" means | 1. Index everything, tell the model what is internal. 2. Skip internal files at ingest. 3. Index everything, filter at retrieval, reject at citation. | Option 3 (`policy.customer_visible`) | `audience != public` or `status in {draft, superseded}` is never retrieved, never shown to the model, and rejected if cited. Keeping the chunks in the index lets a reviewer inspect them and makes "un-hide this document" a one-line change in the live session. Option 1 was rejected because prompt instructions are not a security boundary; Q37 to Q39 in the eval are the proof this is enforced in code. | If a staff-facing mode were needed, the same index serves it with the filter off. | Four documents' worth of embeddings that are never queried (under $0.0001). |
| Which document wins when two disagree | 1. Newest wins. 2. Model decides from the text. 3. Authority tier from folder, with age penalty, applied to the retrieval score and to context order. | Option 3 (`policy.tier_for`, `TIER_WEIGHT`, context sorted by tier) | Newest-wins picks the draft SLA (99.99%) over the approved one. Model-decides answered the refund question from the 2023 FAQ on the first run even with tiers in the headers. The tier order mirrors the Terms of Service s.14.1 (Order Form > Terms > Policies > Documentation), extended to help, blog and community. A document last updated before 2025 drops two tiers, which is the rule that demotes the FAQ. | If the manifest gained an explicit authority column; I would read it instead of inferring from the folder. | Tier table plus an age constant; 30 lines. |
| Ingestion source | Glob the corpus folder; read the manifest | Manifest is the allowlist | Excludes `.DS_Store` and `__MACOSX/` with no special casing, and attaches audience, status, dates and the governance notes to every chunk. A file missing from the manifest is reported, not silently indexed. The `supersedes` column is reversed at read time, so a document another row supersedes is hidden even if its own status was not updated. | A corpus with no manifest; I would fall back to a glob plus a warning. | None. |
| Rebuild safety | Rebuild in place; build into a temp dir and swap | Temp dir plus `os.replace`, and a refusal to delete any directory that does not look like an index | The first version deleted `index/` before calling the embeddings API. With no key or a network error that left the service unable to start until someone ran ingest by hand. Found in the audit, fixed with a test that fails the embedding step on purpose. | Nothing; this is strictly better. | 20 lines. |
| `/reindex` exposure | Open endpoint; path allowlist; token | Corpus path must be inside the repository; optional `RAG_ADMIN_TOKEN` header check | The endpoint exists for the live session's corpus swap. Unrestricted, any client on the port could point the service at arbitrary host files and serve verbatim quotes from them. | If the service were ever exposed beyond a tunnel for a demo, I would require the token unconditionally. | 15 lines. |
| Loaders | LangChain's generic loaders; Unstructured; custom per format | Custom per format, emitting LangChain `Document`s | The generic path loses the DPA's sub-processor table, misaligns the Starter row in the rate-limit table, and would embed `"monthly_usd_minor": 2900` as if it were prose. Each loader handles one named trap and is pinned by a test. | A corpus of hundreds of heterogeneous files, where Unstructured's coverage would beat hand-written loaders. | About three hours, the largest single cost in this task. |
| Chunking | Fixed 500-token windows; by heading section with a 900-character cap; whole document | By section (headings, `dl` pairs, table rows, forum posts, PDF clauses), split only when a section exceeds 900 characters | Sections are the unit a citation naturally points at, and most are already under the cap. Forum posts are one chunk each so the staff reply and the injection post can be ranked differently. | If the eval showed answers needing two adjacent sections; I would add an overlap or a parent-document lookup. | Nine loaders instead of one splitter. |
| Retrieval | BM25 only; dense only; hybrid via RRF | Hybrid: BM25 (k=14) + FAISS (k=14) fused by `EnsembleRetriever`, then each rank score multiplied by the tier weight, top 8 to the model | Exact tokens matter here; dense alone confuses "response.updated" with "response.created". The tier multiplier is applied after fusion so a forum post needs to be more than twice as relevant as a policy chunk to outrank it. | A cross-encoder reranker if the hidden set shows the right chunk in the top 14 but not the top 8; I have not needed it. | Two retrievers to keep in sync; the BM25 index is rebuilt in memory at startup (under a second). |
| Status decision | Model only; code only; model with code overrides | Model drafts; code overrides in three cases | The model is good at "is this answerable" but not at "does this depend on the plan" and not at admitting a bad quote. So: plan-dependent topic with no plan named forces `needs_clarification` (`policy.plan_gate`); `answered` with no surviving citation becomes `insufficient_evidence`; citations that are not verbatim or not customer visible are dropped. | If the gate regex kept producing false positives (it did once; I narrowed it rather than remove it). | Regex list of about ten patterns. |
| Citation verification | Trust the model; verify exact substring; verify with fuzzy match | Exact substring after normalising whitespace and markdown emphasis (trailing punctuation on the quote is forgiven and stripped), against the raw file for Markdown and text, or the extracted text for PDF, Word, HTML tables, CSV and JSON; one repair round trip that may not change the status; then a code-selected fallback sentence restricted to documents the model cited, tiers 1-4, never stale | The brief says quotes must actually appear in the file. Fuzzy matching would let paraphrases through. Verification text is loaded into memory at startup so a concurrent reindex can never make it read a half-written file. The fallback exists because a correct answer was thrown away when the model's quote failed twice; its restrictions exist because the audit showed an unrestricted fallback could attach the stale FAQ's "30-day money-back" sentence to an answer saying the opposite. | If the reviewers require quotes to match the raw bytes of JSON and HTML; I would switch those loaders to quote raw lines and accept uglier citations. | Verification is a substring search over pre-normalised text; negligible. |
| Prompt injection | Prompt instruction only; strip known patterns at ingest; both | Both: `[[...]]` blocks stripped and the post flagged at ingest, forum content tiered lowest, system prompt treats chunk text as data | The one injection in the corpus is inside a forum post that also carries a false claim; the staff correction is in the same thread. Chunking per post lets the correction rank above the attack. Q40 tests injection in the question itself. | A corpus with injections in other syntaxes; I would generalise the stripper. | Ten lines. |
| Confidence field | Omit (null); model's self-estimate; retrieval-score derived | Model's self-estimate, clamped to 0 to 1 | The contract allows null; a self-estimate is cheap and at least separates "I found it" from "I am guessing". It is not calibrated and I say so. | If it were used for routing; then I would derive it from citation count and tier. | None. |

## Known gaps

- Q29 and Q34 fail the eval for reasons discussed in EVAL.md. Q28 now answers both billing
  cycles cleanly but is still graded as a failure against the strict expected status.
- Two redesigns the audit suggested that I have not done: deriving "plan dependent" from
  the retrieved evidence (does the winning chunk enumerate plans?) instead of from question
  regexes, and having the model cite by chunk number with code filling in the verbatim
  quote. Both would remove most of the guardrail code in `answer.py`. Left as the first
  things to do with another day, because they change the eval baseline and I wanted the
  committed numbers to be reproducible.
- The model is not deterministic at temperature 0; expect one or two eval questions to
  move between runs. The fallback citation reduces the impact but does not remove it.
- No conversation memory: if a customer answers the clarifying question, the next `/ask`
  has to restate the plan. The contract is single-turn, so this is by design, but it is
  the first thing a real deployment would add.
- `confidence` is a self-estimate, not calibrated.
- No reranker beyond the tier weight; no caching of embeddings for repeated questions.
- The stale-document rule cannot tell "old but still right" from "old and wrong"; Q34 is
  the consequence.
- `/reindex` rebuilds synchronously and blocks the server for about ten seconds.
